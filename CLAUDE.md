# foldersum

CLI-программа на Python: делает общее саммари по содержимому папки с документами разных форматов
и, по желанию, саммари по каждому файлу. Папка может быть локальной или публичной папкой Google
Drive (по ссылке). Файлы могут быть на русском или английском: язык документа определяется
автоматически. Язык саммари по умолчанию русский (`--lang en` для английского).

Поддерживаемые файлы: PDF (текстовый слой, для сканов OCR), изображения JPG/PNG/WebP/BMP/GIF/TIFF
(OCR), TXT/MD/CSV, DOCX, XLSX, PPTX. Остальное (в т.ч. старые `.doc/.xls/.ppt`) пропускается и
перечисляется в отчёте отдельным списком.

## Статус

Шаги 0-7 выполнены (каркас, scan/fetch, экстракторы и OCR, Ollama-бэкенд и map-reduce, CLI,
Claude-бэкенд, Office-форматы, финальная проверка). Процесс разработки: после каждого шага
остановка на проверки и ревью пользователем, коммит и push только после его OK.

## Быстрый старт

```bash
py -3.14 -m venv .venv && .venv\Scripts\activate && pip install -e ".[dev]"
ollama pull qwen2.5:7b          # локальная модель (бэкенд по умолчанию)

python -m foldersum "https://drive.google.com/drive/folders/<id>" --per-file --output result.md
python -m foldersum D:\docs --lang en --format json
python -m foldersum D:\docs --backend claude            # нужен ANTHROPIC_API_KEY
```

Результат идёт в stdout (UTF-8) или в `--output`, прогресс - в stderr (`--quiet` отключает).

## Окружение

- Python 3.11+ (на машине разработки используется 3.14 в `.venv`).
- Tesseract OCR с языками `rus` и `eng` (Windows: установщик UB Mannheim). Если `tesseract` не в
  PATH, используется `C:\Program Files\Tesseract-OCR`; языковые пакеты ищутся в `~/tessdata`
  (`rus`, `eng`, `osd` из `tessdata_fast`), если задан файл `rus.traineddata` и не задан
  `TESSDATA_PREFIX`.
- Ollama (https://ollama.com), адрес задаётся `OLLAMA_HOST` или `--host`.
- Для `--backend claude`: `ANTHROPIC_API_KEY` (или вход через `ant auth login`). Ключ не хранить в
  коде и git; он нигде не печатается. **С Claude текст документов отправляется в Anthropic.**

## Как вызывать

```bash
python -m foldersum <путь|ссылка Drive> [--per-file] [--backend ollama|claude] \
    [--lang ru|en] [--format md|json] [--output FILE] [--model NAME] [--host URL] \
    [--chunk-chars N] [--download-dir DIR] [--quiet]
```

| Параметр | По умолчанию |
|---|---|
| `--backend` | `ollama` |
| `--model` | `qwen2.5:7b` (ollama), `claude-opus-5-5` (claude; дешевле - `claude-haiku-5-5`) |
| `--chunk-chars` | 4000 (ollama), 100 000 (claude: большинство документов идёт одним запросом) |
| `--download-dir` | `data` (Drive-папка скачивается в `data/<id папки>`) |

`--output` нельзя указывать внутрь сканируемой папки (иначе результат попал бы в следующий скан).
`--host` игнорируется бэкендом claude (с предупреждением).

Коды выхода:

| Код | Значение |
|---|---|
| 0 | успех (в т.ч. если часть файлов не обработалась: они перечислены в отчёте) |
| 1 | нет файлов, либо ни из одного не удалось получить текст |
| 2 | неверный источник или папку нельзя прочитать; также ошибка аргументов командной строки |
| 3 | фатальная ошибка модели (Ollama недоступен, нет модели, неверный ключ, лимиты, таймаут) |
| 4 | ошибка `--output`; если запись не удалась уже после прогона, результат всё равно печатается в stdout |

## Архитектура

```
src/foldersum/
  cli.py              # argparse, выбор бэкенда, коды выхода
  fetch.py            # gdown для ссылок Drive; локальный путь используется как есть
  scan.py             # обход папки, тип файла по сигнатуре, затем по расширению
  models.py           # FileKind, SourceFile, ExtractedDoc(source, text, lang, pages, warnings)
  errors.py           # ExtractionError(+Unsupported/Ocr), LlmError(+LlmContentError)
  langdetect_utils.py # язык документа (ru/en) по доле кириллицы
  ocr.py              # Tesseract; предобработка картинки (серый, масштаб, выравнивание света)
  extractors/
    base.py           # Protocol Extractor
    pdf.py            # pypdf; страницы без текста -> рендер (pypdfium2) + OCR
    image.py          # Pillow (поворот по EXIF, прозрачность на белый) + OCR
    text.py           # txt/md/csv (utf-8, utf-16 с BOM, cp1251); читается не более 10 МБ
    office.py         # docx (python-docx), xlsx (openpyxl), pptx (python-pptx)
  summarizers/
    base.py           # Protocol LlmClient.generate(...), повтор при обрыве по токенам
    ollama.py         # локальная модель (по умолчанию)
    claude.py         # Anthropic API
  prompts.py          # промпты ru/en, ограждение текста тегами, защита от prompt injection
  chunking.py         # разбиение длинных текстов на чанки по строкам/предложениям
  pipeline.py         # map (файлы, длинные режутся на чанки) -> reduce (общее саммари)
  render.py           # Markdown / JSON
tests/                # pytest; бэкенды замоканы (без сети и без модели)
```

Поток: fetch -> scan -> extract -> summarize каждого файла (map) -> общее саммари (reduce) -> вывод.

Что происходит при сбоях:

- Любая проблема с одним файлом (повреждён, нечитаем, OCR недоступен, отказ модели, пустой ответ)
  отмечает только этот файл как «с ошибкой», остальные обрабатываются. Неподдерживаемые типы
  попадают в отдельный список «пропущены».
- Если не удалось составить только общее саммари (содержательная ошибка модели), в отчёте остаются
  саммари файлов, а вместо общего - сообщение.
- Фатальные ошибки модели (нет связи, неверный ключ, нет модели, лимиты, таймаут) останавливают
  прогон с кодом 3.
- Скачанная папка Drive в `data/<id>` при повторном запуске заменяется (чтобы не копились файлы,
  удалённые в Drive), но только если её создал сам foldersum (скрытый файл `.foldersum-download`);
  чужую непустую папку программа не трогает и сообщает об ошибке.

## Claude-бэкенд

Запросы идут без `temperature` и `thinking` (текущие модели их не принимают), с `effort: low` и
запасом 8000 токенов на размышление, для моделей с поддержкой включён серверный fallback при
отказе классификаторов безопасности. Отказ модели - содержательная ошибка файла. **Реальный вызов
API не проверялся (не было ключа):** проверены форма запроса настоящим SDK и обработка ошибок.

## Форматы Office

`.docx`, `.xlsx`, `.pptx` читаются библиотеками без запуска Word/Excel/PowerPoint. Заголовки Word
превращаются в Markdown (`#`), таблицы - в строки `a | b`, листы Excel - в разделы `## Лист`,
слайды - в `## Slide N` (с таблицами, группами фигур и заметками докладчика). Обложки, оглавление
(контентные элементы Word) и вложенные таблицы читаются.

Защита: файл проверяется как zip (до 100 МБ после распаковки и 5000 файлов внутри, иначе отказ);
python-docx и python-pptx не разрешают внешние XML-сущности, openpyxl автоматически использует
`defusedxml` (он в зависимостях); внешние ресурсы не загружаются. Лимиты: 2000 строк на лист и
300 000 символов на файл (с предупреждением).

Не читается (молча пропускается): колонтитулы, сноски, текстовые поля и отслеживаемые правки в
docx; диаграммы и SmartArt в pptx; картинки внутри документов (OCR для них не запускается); значения
формул xlsx без сохранённого результата (файл не открывали в Excel после записи). `.doc/.xls/.ppt`
и `.docm/.xlsm/.pptm` не поддерживаются; docx/xlsx/pptx без расширения (бывает у файлов из Drive)
не распознаются и пропускаются.

## Качество саммари на локальной модели

На `qwen2.5:7b` (4 ГБ VRAM, ~3,7 токена/с) саммари в целом верные, но модель бывает копирует текст
вместо сжатия, иногда придумывает названия и номера разделов и один раз вставила китайский текст;
в цифрах таблиц она тоже может ошибаться (например, путает «тыс.» и «млн»). Пробовали: строгие
промпты, повтор при обрыве по токенам, структурный чанкинг по заголовкам и страницам с контекстом
раздела. Структурный чанкинг не дал однозначного выигрыша и был откачен. Для реальной работы стоит
брать более сильную модель (Claude-бэкенд или крупная локальная), а не крутить промпты.

## Качество OCR

Перед OCR картинка переводится в градации серого, масштабируется до ~2400 px по длинной стороне
и выравнивается по освещению (деление на сильно размытую копию, `ocr.prepare_for_ocr`).
Замер на двух фото страниц кодекса против вручную набранного эталона (доля слов эталона,
найденных точно): было 71,5% / 84,9% (увеличение ×2 + автоконтраст), стало 92,4% / 93,6%.
Проверено и отвергнуто: Otsu и adaptive-бинаризация (хуже), deskew (в пределах погрешности),
`tessdata_best` (+0,6 п.п. в среднем при 2,5x времени). Эталон набран вручную, поэтому цифры
оценочные.
