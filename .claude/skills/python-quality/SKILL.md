# python-quality

Любое изменение Python-кода должно оставлять проект в состоянии, где типы, линтер и тесты проходят. Проверки ловят ошибки дёшево, пока они не попали к пользователю, а "готово" без проверки означает "не знаю, работает ли".

## Требования

1. **Типизация везде.** Аннотации на всех параметрах, возвращаемых значениях и атрибутах классов. Код должен проходить `mypy --strict`. Избегай `Any`; если без него никак, ограничь его одним местом и поясни комментарием. `# type: ignore` допустим только с конкретным кодом ошибки (`# type: ignore[attr-defined]`) и причиной. Для сторонних библиотек без типов ставь `types-*` пакеты или добавляй точечный override в конфиг.
2. **Ruff для линта и формата.** Форматирование делает `ruff format`, линт - `ruff check`. Не используй black, isort, flake8 отдельно: ruff их заменяет.
3. **Pytest, покрытие не ниже 80%.** Для нового и изменённого кода пиши тесты вместе с кодом, а не потом. Покрытие считается через `pytest-cov` и должно быть не ниже 80% по пакету.
4. **Проверки перед завершением.** Не сообщай, что задача выполнена, пока не прогнаны все три команды ниже и они не прошли.

## Порядок работы

1. Посмотри, что уже настроено: `pyproject.toml`, `ruff.toml`, `mypy.ini`, `tests/`. Если конфигов нет, добавь их из раздела "Конфигурация" и поставь dev-зависимости (`ruff`, `mypy`, `pytest`, `pytest-cov`).
2. Пиши код сразу с типами, а не добавляй их потом.
3. Пиши тесты рядом: happy path, граничные случаи, ошибки. Для сети (скрейперы) не ходи в реальный интернет: подменяй HTTP-слой (`monkeypatch`, `responses`, `respx`, `pytest-httpserver`) и держи HTML-фикстуры в `tests/fixtures/`.
4. Перед завершением запусти по порядку:

```bash
ruff format .
ruff check . --fix
mypy --strict .
pytest --cov --cov-fail-under=80
```

5. Если что-то упало - исправь причину и перезапусти всю цепочку, потому что исправление в одном месте могло сломать другое. Не ослабляй проверки (не снижай порог, не добавляй широкие `ignore`/`noqa`), чтобы пройти их. Если проверку реально нельзя выполнить (не установлен инструмент, нет сети), прямо скажи об этом в финальном ответе.
6. В финальном сообщении кратко приведи результат каждой из трёх проверок (прошло/не прошло, процент покрытия).

## Конфигурация (если её нет)

`pyproject.toml`:

```toml
[tool.ruff]
line-length = 100
target-version = "py311"

[tool.ruff.lint]
select = ["E", "F", "W", "I", "B", "UP", "SIM", "C4", "RUF", "N", "S", "PT"]

[tool.ruff.lint.per-file-ignores]
"tests/**" = ["S101"]  # assert в тестах - норма

[tool.mypy]
strict = true
python_version = "3.11"

[tool.pytest.ini_options]
testpaths = ["tests"]
addopts = "--cov --cov-report=term-missing"

[tool.coverage.run]
source = ["src"]  # поправь на реальный пакет
branch = true

[tool.coverage.report]
fail_under = 80
```

Подгони `target-version`, `python_version` и `source` под проект.

## Стиль типизации

- Современный синтаксис: `list[str]`, `dict[str, int]`, `X | None` вместо `List`, `Dict`, `Optional`.
- Структурированные данные - `dataclass`, `TypedDict` или `pydantic`-модели, а не словари произвольной формы.
- Интерфейсы - `Protocol`, коллбэки - `Callable[[...], ...]`.
- Функции без возвращаемого значения помечай `-> None`.
- В тестах тоже ставь аннотации (`def test_x(tmp_path: Path) -> None`), так как `--strict` проверяет и их.

## Что считать готовым

Задача завершена, когда `ruff format --check`, `ruff check`, `mypy --strict` не выдают ошибок, а `pytest` проходит с покрытием не ниже 80%. Любое отклонение от этого нужно явно назвать в ответе пользователю.
